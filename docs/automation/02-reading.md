# 第二阶段：内容精读与结构化落库

## 阶段目标

阅读第一阶段筛选出的论文与行业内容正文，按照项目口径形成清晰、可理解、有证据边界的中文分析，并写入论文索引、周报和行业观点来源数据。这个阶段不手工生成关系图或网站缓存，也不执行发布。

## 开始前读取

- `docs/paper-reading-guide.md`
- `templates/weekly.md`
- `papers/topic_taxonomy.json`（必须完整读取）
- `papers/entity_registry.json`（用于复用已有规范名称，不在本阶段猜测新实体）
- 本期精读候选、对应原文和已有重复论文的周报卡片

## 正文阅读与证据边界

- 按阅读指南的问题链理解研究背景、具体缺口、方法输入与步骤、实验对象与指标、结论边界和实践意义。
- “方法与贡献”必须解释机制如何工作，不能只排列模块名、模型名或攻击名。
- “方法示例”应包含输入、关键处理过程和结果；优先使用论文案例。整理者归纳的例子不得写成作者已经完成的实验。
- 实验数字必须同时交代对象、指标、比较条件或样本规模，不能脱离条件摘录数字。
- 只读取到标题、摘要或元数据时，不补全方法、实验、单位和结论。在 `inquiries/YYYY/` 生成当期“待人工补充论文正文”名单，写明可靠来源、优先级及需要核验的章节或证据。用户补充 PDF 后只读取其明确路径，不移动或删除原文件。

## 论文结构与表达

每篇论文严格按照以下顺序书写：

1. 方向
2. 关键词
3. 名词解释
4. 单位与作者
5. 出处与状态
6. 公开或更新时间
7. 原文链接
8. 核心问题
9. 方法与贡献
10. 方法示例
11. 实验与证据
12. 局限与风险
13. 实践关系
14. 推荐理由

- 正文以中文为主；论文标题、规范处理后的作者名、会议、产品及必要缩写可以保留英文。
- “名词解释”选择理解论文所必需的论文专有概念、协议缩写、攻击前提或不常见计算机术语，每项用一句易懂说明，每篇 1—5 项。它只出现在论文详情和周报，不进入主页面论文卡片。
- “出处与状态”固定为“文献位置｜状态”。文献位置只写会议或 arXiv，状态只使用“预印”或“接收”。arXiv 预印必须说明尚未经过同行评审。
- “公开或更新时间”只记录版本时间线：每项固定写为“时间 预印版本”或“时间 正式发表”；两种时间同时存在时用中文分号连接。不得写基线补录、核验过程、议程更新、修补日期或其他说明。
- 论文的单位与作者必须能与论文作者列表匹配。中国单位使用已核验的官方中文全称；中国学者只有在英文署名与本人一一对应后才使用中文名。存在歧义时保留论文英文署名并进入 inquiries，不凭拼音猜字。

## 主题分类

- 每篇论文只能选择一个主领域。
- 研究对象、安全问题、研究方法和成果类型使用可多选的受控细分标签，不能把不同维度混在同一层。
- 新标签必须先加入 `papers/topic_taxonomy.json`，给出中文显示名和正确 facet，再写入索引。
- 主领域无法由现有规则唯一确定时，增加显式 `primary_domain_overrides`，不能依赖规则顺序静默归类。
- 分类表按版本长期维护。改名、合并或废弃标签时保留别名或迁移关系，不直接破坏历史条目。

## 论文落库与清单

- 新论文写入 `papers/index.jsonl` 并在本期 `weekly/YYYY-Www.md` 保存完整精读。
- 已存在论文出现正式发表、DOI、新版本或内容修正时更新原索引和原周报卡片，不新增重复项。
- 正式完成落库后从 `papers/watchlist.jsonl` 移除对应候选；暂缓或排除项继续保留，并更新 `status`、`last_checked`、`target_week` 和 `decision_note`。
- 按 `README.md`、`templates/weekly.md` 和阅读指南维护本期概览、精选论文、值得追踪、既有论文关系及筛选说明，不杜撰任务不可见的聊天或用户判断。

## 行业观点落库

- 通常精选 2—5 篇真正有证据基础的公开内容，宁缺毋滥。
- 每条 `industry/viewpoints.json` 记录必须包含 `source_type`、`content_type`、`evidence_basis`、`limitations`、`commercial_interest`，以及标题、来源、日期、链接、主题、摘要和重点。
- 摘要与重点必须来自可访问正文；明确区分作者或厂商主张、底层证据和整理者判断。
- 有条件时链接底层报告、数据、漏洞公告或相关论文。商业利益、方法限制和无法独立验证的部分必须明确记录。

## 第二阶段完成检查

- [ ] 每篇论文均读取了正文；没有正文的项目已进入 inquiries 且未被补写。
- [ ] 每篇论文的 14 个字段顺序正确、内容完整。
- [ ] 核心问题、方法、示例和实验能让未读原文的技术读者理解，不是名词罗列。
- [ ] 每篇论文有 1—5 个真正需要解释的名词，格式统一。
- [ ] 状态、版本时间线和链接符合证据，不含“基线补录”等过程说明。
- [ ] 主领域唯一，所有细分标签和 override 均符合完整读取后的受控词表。
- [ ] 作者与单位来自论文或可靠事实表；所有歧义均保留英文或进入 inquiries。
- [ ] 论文已按 DOI、arXiv ID、正式 URL、规范化标题去重，并正确维护索引、周报和清单。
- [ ] 行业观点字段、证据基础、限制和商业利益完整，没有将厂商主张直接写成独立事实。

所有检查通过后才能进入第三阶段。
