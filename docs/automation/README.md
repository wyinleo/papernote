# Papernote 每周自动化执行手册

本目录是“每周安全论文动态与 Papernote”任务的长期规则来源。自动化卡片只负责启动和编排；检索、阅读、数据维护与发布的详细要求在这里分片维护，避免卡片随着需求增长而不断变长。

## 单次运行顺序

每次运行由同一个主任务依次完成三个阶段：

1. 完整读取并执行 [`01-discovery.md`](01-discovery.md)。
2. 第一阶段完成检查通过后，完整读取并执行 [`02-reading.md`](02-reading.md)。
3. 第二阶段完成检查通过后，完整读取并执行 [`03-maintenance.md`](03-maintenance.md)。

进入每个阶段时必须重新读取对应分片及其列出的事实文件，不能只依赖任务开头的概括或上次运行记忆。每个阶段完成后逐项执行该分片末尾的完成检查；能够修正的问题先修正，无法核验的问题进入当期 `inquiries/`。第三阶段的构建与发布检查未通过时不得推送或声称已经部署。

## 文件职责

| 文件 | 唯一负责的规则 |
| --- | --- |
| `01-discovery.md` | 新论文和行业内容的检索、来源优先级、去重、候选筛选与待办清单 |
| `02-reading.md` | 正文阅读、中文精读、名词解释、主题分类、周报与行业观点落库 |
| `03-maintenance.md` | 历史状态回查、作者与单位实体、学术关系、站点构建、交互验证、Git 与发布 |
| `../paper-reading-guide.md` | 单篇论文的阅读问题链、方法示例和表达质量 |
| `../../templates/weekly.md` | 周报的固定结构和字段顺序 |
| `../../papers/topic_taxonomy.json` | 主题和多维细分标签的受控词表 |
| `../../papers/entity_registry.json` | 人名、单位、主页、别名和核验来源的事实表 |

`papers/index.jsonl` 是论文事实主索引，`weekly/` 是中文精读和结构化“单位与作者”的来源，`industry/viewpoints.json` 是公开行业观点库，`papers/watchlist.jsonl` 是内部论文候选队列。

`papers/academic_graph.json` 和 `site/data.js` 均为生成物，只能由 `scripts/build_site.py` 重建，不得手工修改。

## 执行原则

- 三个阶段串行执行。检索结果确定后才能开始精读，精读落库完成后才能维护、构建和发布。
- 主任务负责阶段切换、规则读取、结果合并和最终校验。阶段内部只有彼此独立的检索、论文阅读或主页调查才适合并行；同一源文件的写入和发布必须串行完成。
- 只根据可访问的可靠来源写事实。只能取得题目、摘要或元数据时，不补全正文中的方法、实验、单位或结论。
- 保留运行开始前已经存在的用户改动。只暂存本次任务相关文件，不覆盖或顺带提交无关修改。
- “宁缺毋滥”优先于凑足篇数；无法核验时明确保留不确定性，不用名气、拼音猜测或作者自述替代证据。
- 任务中发现可以确定修正的问题应在本次安全修正并验证；仅当缺少正文、身份对应或外部证据时才写入 inquiries。

## 后续规则如何分片

新增长期要求时按以下方式维护：

1. 先判断它改变的是检索、阅读还是维护与发布。
2. 只写入负责该行为的一个分片，避免在卡片、README 和多个分片中重复。
3. 访客可见的产品行为发生变化时，再同步更新项目根目录 `README.md`；论文卡片字段发生变化时同步更新 `templates/weekly.md`；阅读方法发生变化时同步更新 `docs/paper-reading-guide.md`。
4. 能由程序确定的约束应加入 `scripts/build_site.py --check` 或相应测试，文档主要保留需要判断的口径和证据标准。
5. 只有总目标、阶段顺序、入口文件或停止条件变化时，才需要修改自动化卡片。

不要把一次性的网络故障、临时页面异常或单篇论文特例扩大为长期规则。需要保留的特例优先写入相应数据记录、`primary_domain_overrides` 或当期 inquiries。
