# Papernote 的数据与加载方案

## 当前决定

继续用 Git 管理 Markdown 周报、JSONL 论文索引和 JSON 实体表，由 Python 构建静态发布文件。页面采用轻量目录、按需 JSON 和页面内缓存。这个组合适合目前每周更新、以阅读为主、部署在 GitHub Pages 的项目，不需要维护在线数据库服务。

2026-09-25 的 98 篇论文、162 个单位、486 位学者数据中，原单文件约 897,414 字节；拆分后首页目录为 299,663 字节，减少约 66.6%。这是 UTF-8 未压缩的数据文件体积，不含底图、脚本、样式；不等于实际网络时间或整页速度提升比例。

## 文件与处理流程

| 层级 | 保存内容 | 读取时机 |
| --- | --- | --- |
| 源文件 | 周报正文、事实索引、实体与地理归属、`papers/easycatch.json` 通俗解释 | 每次构建；保持可读、可审查的 Git 差异 |
| `site/data.js` | 论文卡片、分类、计数、作者姓名及资源地址 | 首页启动 |
| `site/data/paper-<hash>.json` | 单篇完整精读、Easycatch、名词解释、引用链接 | 打开该论文详情 |
| `site/data/academic-<hash>.json` | 学者档案、单位、论文与合作边 | 首次进入学术关系或打开学者详情 |
| `site/data/search-<hash>.json` | 某一周的完整可检索文本 | 首次搜索涉及该周的内容；主题搜索可涉及多周 |

正文与搜索数据分开，保证搜索仍能找到正文中的实验术语。例如首页卡片没有 `memcmp`，全文搜索仍可找到 AEX-NStep 的方法示例。地图的国家计数始终对论文 ID 去重；同一论文在同一国家出现多家单位也只记一次。

文件名采用内容哈希。相同内容的资源路径不变，修改一篇正文只改变该篇详情和对应周搜索文件的地址。浏览器 HTTP 缓存遵循托管服务器的实际响应头，本项目没有宣称设置 GitHub Pages 无法控制的长期缓存头。页面内会复用成功请求，合并并发请求，失败允许重试，并在 15 秒后取消尚未完成的网络请求。切换详情或关闭弹窗后，旧请求不能覆盖当前页面。

`site/data/` 是构建产物且已加入 `.gitignore`；GitHub Actions 在部署前生成，不需要提交每篇正文的副本。每次发布从干净 checkout 构建，避免将本地历史产物全部上传。已有浏览器标签在部署后若请求到被替换的旧版本资源，可刷新页面取得新的目录。单篇详情与地图都显示加载和失败状态。

搜索输入延迟 150 毫秒处理，复用已生成的小写搜索文本。悬停地图只切换相关 SVG 连线的可见性，不重新汇总数据，也不重建国家路径。

## 规模继续增长时

优先根据测量决定下一步。记录目录字节数、首次关系图加载量、构建时间和目标设备上的筛选响应时间。可以将目录超过 1 MiB、关系数据超过 2 MiB 或交互频繁超过 100 毫秒作为重新评估的工程预警；这些是本项目可调整的预算，不是数据库的容量上限。

1. 目录继续增长时，将论文卡片按周或年份切片，主题视图分页，避免一次创建所有卡片。把行业内容也移到按需文件。
2. 关系图变大时，构建期输出国家汇总、按年份 / 学科的合作边；学者详情按人加载。让浏览器只下载当前视图需要的关系。
3. 历史回查与构建查询成为瓶颈时，引入 **SQLite 作为本地或构建阶段的可重建索引**。表可分为论文、学者、单位、署名关系，分别索引论文 ID、年份、会议、单位国家代码；用事务更新变更的论文，并生成相同的静态资源。例如查询“2026 年中国与新加坡的共同论文”可通过署名关系表联结完成。
4. 需要实时写入、多端账户或服务端全文搜索时，再评估 SQLite + API 或托管 PostgreSQL。此时需要新增后端托管、权限和备份。当前任务没有引入这些服务。

直接让浏览器下载整个 SQLite 文件仍然需要传输整库，不能单靠更换文件格式解决首页加载问题。SQLite 的主要价值在于结构化查询、约束和增量维护；静态分片负责控制访客需要下载的数据量。

## 验证

```bash
python3 scripts/build_site.py --check
python3 scripts/build_site.py
python3 -m unittest discover -s tests
node tests/test_academic_map.js
node tests/test_asset_loader.js
```

测试覆盖正文与搜索完整性、内容哈希更新、目录体积、并发请求复用、失败重试、国家计数去重和合作筛选。UI 还需验证地图悬停 / 聚焦、详情往返、全文搜索及窄屏布局。

参考：[SQLite 适用场景](https://www.sqlite.org/whentouse.html)、[MDN HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)。
