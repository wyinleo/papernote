# Papernote 论文阅读与整理指南

这份指南用于统一每篇论文的阅读顺序和落库表达。目标是让没有读过原文的技术读者能够理解：论文解决什么问题、方法怎样工作、有哪些核心贡献，以及结果能否用于实践。

## 1. 确认论文身份

- 优先使用会议官方论文集、DOI、作者公开全文或 arXiv 原文。
- 核对标题、作者、单位、公开时间和发表状态。
- 只有 arXiv 来源时标为“预印”。

## 2. 按问题链阅读

阅读时依次回答四个问题：

1. **为什么要做**：如果是旧场景，现有系统或方法在哪种具体场景失效？如果是新场景，作者发现了哪些新的安全问题？
2. **怎样解决**：论文提出了什么机制，它接收什么输入、经过哪些关键步骤、产生什么结果？
3. **证据怎样**：实验对象、样本规模、比较基线和指标是什么？有哪些发现或者独特观点？
4. **边界在哪**：威胁模型、数据来源、环境影响、成本或尚未验证的条件有哪些？

## 3. 写一个易于理解的方法示例

- “方法示例”应包含数据输入、处理过程和数据分析结果。
- 优先使用论文中的案例。
- 语言通俗易懂，本科生知识学生也可以方便理解。

## 4. 选择名词解释

- 每篇选择不超过 5 个理解论文所必需的术语。
- 优先解释论文专有概念、协议缩写、攻击前提和不常见的系统术语。
- 使用“名词解释”的格式，说明它是什么，并尽量点明它与本文的关系。
- 不解释标题中一眼可懂的普通词，也不把关键词原样复制成另一组名词列表。

## 5. 按固定字段落库

周报中的论文依次填写：方向、关键词、名词解释、单位与作者、出处与状态、公开或更新时间、原文链接、核心问题、方法与贡献、方法示例、实验与证据、局限与风险、实践关系、推荐理由。

写完后检查：

- 核心问题是否同时交代背景、缺口和研究问题；
- 方法是否说明关键步骤，而不只是列系统名；
- 示例是否让读者能跟随一次完整过程；
- 实验数字是否带有对象、指标或比较条件；
- 局限是否约束了结论的适用范围；
- 名词解释是否不超过 5 条且每条都有实际解释。

完成精读后，使用 [`papernote-easycatch`](../skills/papernote-easycatch/SKILL.md) 将问题、方法和边界转成两段解释：生活故事或实际使用场景与论文思路，保存在 `papers/easycatch.json`。读者反馈和转化规则的迭代统一维护在该 skill 中。

最后运行：

```bash
python3 scripts/build_site.py --check
python3 scripts/build_site.py
```

校验通过后，生成器会从周报和论文索引重建网页数据；不要直接编辑 `site/data.js` 或 `papers/academic_graph.json`。
