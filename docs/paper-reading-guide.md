# Papernote 论文阅读与整理指南

这份指南用于统一每篇论文的阅读顺序和落库表达。目标不是复述摘要，而是让没有读过原文的技术读者能够理解：论文解决什么问题、方法怎样工作、证据是否足够，以及结果能否用于实践。

## 1. 先确认论文身份

- 优先使用会议官方论文集、DOI、作者公开全文或 arXiv 原文。
- 先核对标题、作者、单位、公开时间和发表状态，再开始写内容。
- 只有 arXiv 来源时标为“预印”，不把投稿说明或论文模板当成正式接收证据。

## 2. 按问题链阅读

阅读时依次回答四个问题：

1. **为什么要做**：现有系统或方法在哪个具体场景失效？
2. **怎样解决**：论文提出了什么机制，它接收什么输入、经过哪些关键步骤、产生什么结果？
3. **证据怎样**：实验对象、样本规模、比较基线和指标是什么？数字支持的是哪项主张？
4. **边界在哪**：威胁模型、数据来源、环境、成本或尚未验证的条件有哪些？

不要把术语和模块名称堆成“方法与贡献”。每个关键机制至少用一个因果句说明，例如：“系统先从补丁中找出新增校验，再把校验转成可执行规则，最后到其他项目中搜索缺少同类校验的调用点。”

## 3. 写一个能走通的方法示例

“方法示例”应包含起点、处理过程和结果。优先使用论文中的案例；如果是整理者归纳的例子，要明确保持在论文方法允许的范围内，不能写成作者已经做过的实验。

例如，介绍 RAG 投毒时，不只写“使用向量嵌入优化恶意文档”，而应解释：用户询问 SSH 配置，普通恶意指令与查询不相似而不会被检索；攻击者给恶意文档加入与 SSH 问题相似的短前缀，使它进入检索结果，随后其中的指令才有机会影响智能体。

## 4. 选择名词解释

- 每篇选择 1–5 个理解论文所必需的术语。
- 优先解释论文专有概念、协议缩写、攻击前提和不常见的系统术语。
- 使用“术语：一句话解释”的格式，说明它是什么，并尽量点明它与本文的关系。
- 不解释标题中一眼可懂的普通词，也不把关键词原样复制成另一组名词列表。

## 5. 按固定字段落库

周报中的论文依次填写：方向、关键词、名词解释、单位与作者、出处与状态、公开或更新时间、原文链接、核心问题、方法与贡献、方法示例、实验与证据、局限与风险、实践关系、推荐理由。

写完后检查：

- 核心问题是否同时交代背景、缺口和研究问题；
- 方法是否说明关键步骤，而不只是列系统名；
- 示例是否让读者能跟随一次完整过程；
- 实验数字是否带有对象、指标或比较条件；
- 局限是否约束了结论的适用范围；
- 名词解释是否不超过 5 条且每条都有实际解释。

最后运行：

```bash
python3 scripts/build_site.py --check
python3 scripts/build_site.py
```

校验通过后，生成器会从周报和论文索引重建网页数据；不要直接编辑 `site/data.js` 或 `papers/academic_graph.json`。
