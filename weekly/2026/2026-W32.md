### 1. “Do Not Mention This to the User”: Detecting and Understanding Malicious Agent Skills in the Wild

- **方向**：人工智能安全 / 智能体扩展供应链
- **关键词**：智能体技能、恶意扩展、动态验证、凭据窃取、指令劫持
- **单位与作者**：
  - Griffith University：Yi Liu、Zhihao Chen、Yanjun Zhang、Leo Yu Zhang
  - Nanyang Technological University：Gelei Deng
  - University of New South Wales：Yuekang Li
  - 浙江理工大学：Jianting Ning
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-02-06 预印本公开；2026-07-28 正式议程更新
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/liu-yi)、[arXiv 原文](https://arxiv.org/abs/2602.06547)
- **核心问题**：编程智能体的第三方 skill 同时包含自然语言说明和可执行辅助脚本，安装后往往继承本地用户权限。现有扫描只能发现“可疑”网络、进程或凭据操作，难以判断它们是工具功能还是蓄意攻击。论文要解决的是：如何从快速扩张的公共技能生态中建立行为已确认的恶意样本，并刻画攻击链、攻击者策略和规避方式。
- **方法与贡献**：作者从两个注册表采集 98,380 个技能，先用静态规则将范围缩至 4,287 个候选，再在隔离容器中生成三类调用并动态观察行为，最后由两名研究者结合日志和代码独立复核。由此确认 157 个恶意技能、632 个漏洞实例和 13 类攻击技术，并区分凭据窃取型“Data Thieves”与通过文档指令操纵智能体的“Agent Hijackers”。
- **方法示例**：一个名为计算器的技能在 `SKILL.md` 中只声明四则运算，但辅助脚本会连接远端地址、把标准输入输出重定向到套接字并启动 shell。检测流程不仅匹配网络和进程 API，还在沙箱中调用技能并核对“声明功能—实际行为”的差异，从而把它从普通安全工具中区分出来。
- **实验与证据**：动态流程确认 157/98,380 个恶意技能，包含 632 个漏洞，平均每个技能 4.03 个漏洞并跨越中位数 3 个攻击阶段；两名标注者的恶意判定一致性为 Cohen’s κ=0.89。54.1% 的恶意技能来自单一发布者，84.2% 的漏洞位于自然语言文档层。负责任披露后，注册表维护者移除或下架了全部 157 个报告样本。
- **局限与风险**：数据是 2026 年 1 月公共注册表快照，不能代表企业私有技能；60 秒动态窗口可能漏掉延迟或环境门控载荷，Docker 也可能被攻击者识别。单一发布者占比过高会影响总体分布；作者抽样发现未确认候选中仍有大量休眠触发器，因此 157 更接近已确认下界。
- **实践关系**：技能市场不能只扫描脚本，必须同时检查自然语言指令、隐藏能力和运行时行为；安装前签名、最小权限、网络与凭据隔离、声明能力与实际调用的差分审计应成为默认供应链控制。
- **推荐理由**：它把“恶意智能体技能”从案例讨论推进为有行为证据、可复核数据和实际下架结果的生态测量，是理解新型智能体供应链风险的关键基线。

### 2. Measuring Real-World Prompt Injection Attacks in LLM-based Resume Screening

- **方向**：人工智能安全 / 文档提示注入
- **关键词**：简历筛选、隐藏文本、提示注入、多模态检测、实证测量
- **单位与作者**：
  - University of North Carolina at Chapel Hill：Mohan Zhang、Tianlong Chen
  - Duke University：Yuqi Jia、Neil Zhenqiang Gong
  - Arizona State University：Zhen Tan
  - hireEZ：Steven Jiang
  - University of California, Berkeley：Dawn Song
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-05-27 预印本公开；2026-07-28 正式议程更新
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/zhang-mohan)、[arXiv 原文](https://arxiv.org/abs/2605.28999)
- **核心问题**：提示注入通常在合成基准中研究，但招聘系统会真实处理攻击者控制的 PDF 简历。隐藏文本既可能是“忽略规则、直接录用”的显式指令，也可能是肉眼不可见、却能进入解析器的技能与经历数据。论文研究这种攻击在真实招聘数据中出现多少、如何演化，以及通用文本检测器为何失效。
- **方法与贡献**：论文提出两条互补检测路径：HCD 从 PDF 结构、字号、颜色对比和渲染位置定位机器可读但人眼不可见的片段，再用模型做语义复核；VDA 则比较完整渲染图与提取文本。作者先交叉验证和人工抽查，再用成本更低的 HCD 对两个去标识化数据集做长期测量。
- **方法示例**：一份简历把“Python、Java、10 年云架构经验”设为与背景同色的小字。纯文本解析会把这些资格送入筛选模型，而招聘人员看不到。HCD 先根据字体和颜色发现局部隐藏区，只把该片段交给模型判断是否是操纵性内容，避免让模型审阅整份 PDF。
- **实验与证据**：两个数据集分别含 83,277 和 113,405 份简历，共 196,682 份。HCD 标出 2,030 份隐藏注入简历：近期匹配数据为 1.19%，长期 ATS 数据为 0.91%。90.5% 与 95.7% 的样本属于隐藏“数据注入”而非显式命令。人工验证估计 HCD 精度 86.1%，平均每份 1.35 秒、约 0.0001 美元；通用检测器要么召回极低，要么误报极高。
- **局限与风险**：作者只抽查了 100 份双检测器均判定为正常的简历，无法给出精确召回率，因此 1% 应理解为保守下界。数据来自单一招聘平台，且论文没有测量隐藏内容是否真的改变录用或排序结果；人口与行业差异也可能受数据来源和自选择影响。
- **实践关系**：招聘、保险、内容审核等文档型大模型应用不能只检测“忽略前文”之类文本模式，应校验机器提取层与人类可见渲染层是否一致，并把隐藏字段、OCR 层和元数据视为不可信输入。
- **推荐理由**：这项工作用近 20 万份真实文档证明提示注入已不是实验室假设，并揭示主流研究关注的显式指令只占现实攻击的小部分。

### 3. Semantics Over Syntax: Uncovering Pre-Authentication 5G Baseband Vulnerabilities

- **方向**：网络与通信安全 / 5G 基带
- **关键词**：5G RRC、认证前攻击面、语义约束、基带测试、拒绝服务
- **单位与作者**：
  - University at Buffalo：Qiqing Huang、Xingyu Wang、Hongxin Hu
  - Texas A&M University：Wanda Guo、Guofei Gu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-04-05 预印本公开；2026-07-28 正式议程更新
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/huang-qiqing)、[arXiv 原文](https://arxiv.org/abs/2604.04283)
- **核心问题**：5G 终端在完成认证和完整性保护前就必须解析 RRC 配置消息。已有模糊测试偏重破坏 ASN.1 语法，而攻击者可以发送编码完全合法、字段值或跨字段关系却违反规范语义的消息，让基带进入实现未覆盖的状态。论文要系统化发现这种“语法通过、语义冲突”的认证前漏洞。
- **方法与贡献**：CONSET 从 3GPP 规范提取值域、字段存在性、同一信息元素内部依赖和跨信息元素依赖，统一成可执行 DSL；其中自然语言依赖由 LLM 在必须引用规范证据、通过值域与可满足性检查的条件下辅助提取。工具只改变触发约束所需的最小字段，再重新编码，并分别在 OAI 开源终端与 SDR 隔离基站上的商用手机执行。
- **方法示例**：规范要求 `SearchSpace` 与 `ControlResourceSet` 使用同一标识。CONSET 保持两字段都在各自合法值域内，只把一个标识从 2 改成 1，消息仍可被 ASN.1 编解码器接受，却打破跨字段语义关系；若基带直接把该关系当作前提，就可能触发断言或崩溃。
- **实验与证据**：作者测试 8 款商用 5G 手机、覆盖 4 个芯片系列，确认 7 个此前未知问题，其中 3 个 MediaTek 高危 CVE 已修复；论文估计受影响范围涵盖 64 个芯片型号和 542 款以上手机。OAI UE 上发现 29 个独立崩溃点。对 6,000 个字段对，约束引导生成 1,458 个输入、耗时 0.76 天，而枚举生成 30,600 个输入、耗时 15.94 天。
- **局限与风险**：商用基带是黑盒，论文只能依据 logcat、掉线和重启现象保守声称拒绝服务，不能据此推断代码执行。端到端实验集中在 `RRCSetup`；LLM 规则提取依赖 3GPP 文本质量和证据门控，跨更多协议的可迁移性只有初步结果。设备样本也不足以概括所有厂商实现。
- **实践关系**：协议实现测试应把规范中的“shall”“only if”和跨字段标识关系转成机器可执行不变量；认证前路径需要在解码后再次做值域、索引和引用一致性检查，并以失败返回替代断言终止。
- **推荐理由**：论文把规范语义转成高效、可归因的黑盒测试输入，并用 CVE、真实设备和开源崩溃点共同证明认证前语义检查是可操作的防御缺口。

### 4. Cutting the Gordian Knot: Detecting Malicious PyPI Packages via a Knowledge-Mining Framework

- **方向**：软件与应用安全 / 软件包供应链
- **关键词**：PyPI、恶意软件包、行为序列、知识挖掘、程序分析
- **单位与作者**：
  - Nanyang Technological University：Wenbo Guo、Yiran Zhang、Jiahui Wu、Vinay Sachidananda、Yang Liu
  - 南开大学：Chengwei Liu
  - 四川大学：Ming Kang
  - Imperial Global Singapore：Zhengzi Xu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-01-23 预印本公开；2026-07-28 正式议程更新
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/guo-wenbo)、[arXiv 原文](https://arxiv.org/abs/2601.16463)
- **核心问题**：PyPI 恶意包检测器常把网络请求、编码和文件操作等合法功能误报为恶意，15%—30% 的误报率会制造不可承受的人工队列。论文认为缺口不在于缺少更多孤立规则，而在于缺少能区分相同 API 序列在不同上下文中意图的行为知识。
- **方法与贡献**：PYGUARD 先从四种静态工具的误报和漏报中抽取代码上下文，将 API 调用转成动作序列，再用分层频繁模式挖掘获得 304 个区分性模式。确定性模式直接分类；需要语境判断时，用检索到的良性与恶意相似案例约束 LLM 推理，从而保留执行序列和上下文，而不是只看单个函数名。
- **方法示例**：良性图像工具和窃密包都可能调用 URL 编码与 Base64。PYGUARD 不因这两个 API 就报警，而是检查数据来源和后续序列：若读取系统凭据、编码并发送到外部地址，行为链与恶意模式一致；若只编码用户提供的图像数据，则由良性案例提供反证。
- **实验与证据**：留出测试集含 2,394 个良性与 2,363 个恶意包。PYGUARD 达到 99.50% 准确率、仅 2 个误报和 19 个漏报；新近包数据准确率 97.37%，混淆代码数据 98.28%。2024 年 3—6 月部署期间，系统发现 219 个未在 OSV/Snyk 记录的恶意包，经 PyPI 确认后移除；这些包三个月内合计下载 39,420 次。迁移到 NPM 后准确率为 98.07%。
- **局限与风险**：框架分析 Python 文件中的行为，无法覆盖依赖混淆、运行时从远端安装代码或藏在非 Python 文件中的载荷。LLM 仍可能幻觉，虽然确定性规则与检索案例降低了风险。真实部署发生在 2024 年，其攻击分布可能与 2026 年生态不同；平均每包 34.09 秒也需要在大规模流水线中评估成本。
- **实践关系**：供应链平台应把历史误报和漏报转成可持续更新的行为知识，先用确定性序列筛选，再把少量模糊样本交给语境推理；同时必须用依赖图、构建沙箱和非代码资产扫描补足其盲区。
- **推荐理由**：论文同时给出留出集、混淆集、跨生态和真实下架证据，说明“从检测失败中学习行为边界”可以显著降低供应链告警疲劳。

### 5. Send and Pretend: Exploiting Transcript Consistency Issues in End-to-End Encrypted Group Chats

- **方向**：网络与通信安全 / 端到端加密群聊
- **关键词**：会话记录一致性、消息等价分叉、群聊投票、Sender Key、协议分析
- **单位与作者**：
  - Interdisciplinary Transformation University (IT:U)：Gabriel K. Gegenhuber
  - University of Vienna：Moritz Grefner、Matthäus Wininger、David Schmidt、Aljosha Judmayer
  - SBA Research：Maximilian Günther
  - CDL AsTra：David Schmidt
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-07-29 预印本公开；2026-07-31 更新并进入正式议程
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/gegenhuber)、[arXiv 原文](https://arxiv.org/abs/2607.27510)
- **核心问题**：端到端加密保护消息不被服务器或网络窃听，却不一定保证群成员最终看到相同的消息序列。恶意群成员控制自己的客户端后，可以合法使用点对点通道、重传回退或不同 Sender Key 广播，使不同成员看到不同内容；投票等高层功能会把这种差异渲染为“权威结果”。
- **方法与贡献**：作者在 WhatsApp、Signal、iMessage 和 Threema 上修改发送端客户端，系统测试 Sender Key、点对点端到端通道、解密失败回退和重复广播。攻击者只需是普通群成员，不控制服务器、不破坏密码算法。论文把消息省略、改写、顺序差异、设备差异和投票操纵映射到协议路径，并提出在现有 Sender Key 上增加一致性检测的低开销方案。
- **方法示例**：攻击者向大多数成员发送正常会议链接并获得正面表情反应，同时用相同消息标识向目标发送钓鱼链接。目标看到的恶意链接旁会显示其他成员对“同一消息”的正面反应，而管理员仍只看到正常链接，现有客户端不会提示分叉。
- **实验与证据**：四个主流应用在群聊场景都允许消息等价分叉；WhatsApp 和 Signal 的回退路径、iMessage 与 Threema 的点对点群消息都可被利用。论文还在四个平台的投票中演示选项重排、不同问题、隐藏额外票或覆盖结果等攻击，并公开修改客户端与复现实验。四家厂商均确认收到披露；Meta 支付 1,000 美元奖金，但截至 2026-07-29 尚无平台宣布协议级一致性修复。
- **局限与风险**：威胁模型要求攻击者已在群中并能控制自己的客户端；研究未进行大规模用户实验，因此尚不清楚真实用户会多常察觉异常。样本只覆盖四个应用与当时版本，新协议如 MLS 的应用消息层仍需单独评估。公开 PoC 也会提高短期滥用风险。
- **实践关系**：产品不能把“端到端加密”当作群聊完整性的同义词。群消息和投票需要可验证的群级发送承诺、成员间摘要对比或明确的分叉警告；高风险协调不应只依赖客户端渲染的一致外观。
- **推荐理由**：它揭示的是跨平台设计缺陷而非单一实现 bug，并把抽象的一致性属性落到钓鱼、规避审核和操纵投票等直接可理解的攻击。

### 6. Not In My Git Yard: Catching Backdoors at Commit and Release Time

- **方向**：软件与应用安全 / 持续集成供应链防御

- **公开或更新时间**：2026-07-29 公开
- **原文链接**：[arXiv 原文](https://arxiv.org/abs/2607.26719)
- **核心问题**：开源后门可能混入普通提交、发布包或依赖更新，而传统 CI 只检查功能回归，二进制后门分析又难以在每次提交的十分钟级预算内完成。论文希望在不淹没维护者的前提下，判断新版本是否出现“以前没有、且偏离当前版本正常行为”的秘密触发路径。
- **方法与贡献**：Lily 复用 CI 中的短时灰盒模糊测试，以系统调用集合描述运行行为；只有某行为在旧版本不存在、且对新版本回归语料而言异常时才报警。随后把触发输入、系统调用差异与代码变更关联，将数千到数百万行发布差异缩小到少量可审阅代码。论文还分析五类规避策略并给出选择性硬化模式。
- **方法示例**：若一次提交加入只有特殊用户名 `:)` 才触发的远程 shell，Lily 的模糊测试找到该输入后，会看到新版首次出现 shell 相关系统调用，而且它不属于新版回归测试的常态；报告再把行为追溯到处理用户名的变更行，而不是要求维护者逆向整个二进制。
- **实验与证据**：作者在 13 个开源项目上进行 20 次、每次 10 分钟的重复试验，覆盖 432 个正常提交、13 个后门提交、50 个正常发布和 50 个后门发布。平均提交检测率 90%、发布检测率 83%，正常提交误报 0.2%、发布误报 4.3%；所有后门至少在一次重复中被发现，报告通常把数百万行差异压缩到不足 12 行。
- **局限与风险**：13 个后门中只有 3 个来自真实事件，其余为基准中的合成但现实化样本，不能代表所有语言、构建系统和触发逻辑。检测依赖现有 fuzz harness 与十分钟内能否到达触发路径；攻击者污染历史语料会显著降低普通模式检测率，硬化模式虽可恢复检测，却把提交和发布误报提高到约 3% 与 18%。此外，公开稿虽写有 ASE 2026 和 DOI，但本期无法从可访问的官方程序或已注册 DOI 独立核验，因此仍按预印处理。
- **实践关系**：成熟项目可把短时行为差分作为 CI 的第二条安全轨道，并定期使用更严格模式抽查；它应与可复现构建、提交签名、依赖锁定和人工代码审查组合，而不能单独承担供应链完整性。
- **推荐理由**：论文把后门检测压进现实 CI 预算，并坦率量化硬化、误报和语料投毒之间的权衡，对维护大型开源项目很有工程参考价值。

### 7. MemSecBench: Tracking Agent Memory Poisoning from Persistence to Consequence and Repair

- **方向**：人工智能安全 / 智能体记忆
- **关键词**：记忆投毒、持久化、外部后果、选择性修复、评测基准
- **单位与作者**：
  - 浙江工业大学：Xuanze Chen、Xukang Xie、Wentao Fu、Jiajun Zhou、Shanqing Yu、Qi Xuan
- **出处与状态**：arXiv｜预印
- **公开或更新时间**：2026-07-29 公开
- **原文链接**：[arXiv 原文](https://arxiv.org/abs/2607.27080)
- **核心问题**：智能体记忆安全不能只问“恶意文本是否被写入”，还要追踪它是否在后续会话被召回、被模型采纳、造成可验证的外部后果，以及用户要求删除后能否只移除恶意语义而保留正常记忆。既有基准往往只覆盖这条生命周期的一部分。
- **方法与贡献**：MemSecBench 构造 310 个 Write—Execute—Forget 案例，来自代码与科研、日常生活、办公三类共 48 个上下文。每个案例定义恶意语义、必须保留的良性记忆、外部后果和七个证据检查点；在两个智能体框架、四种记忆后端、三个模型后端组成的 24 个配置中，以确定性写入检查、程序化外部证据和独立裁判模型共同判定。
- **方法示例**：供应商文档声称某付款流程只在 6 月 30 日前有效。若记忆系统保存账号却丢失截止日期，7 月处理发票时会把临时规则当作长期偏好。Forget 阶段不仅检查旧账号是否删除，还检查其他合法供应商偏好是否仍在，避免用“清空全部记忆”伪装成修复成功。
- **实验与证据**：跨 24 个配置的宏平均显示，恶意记忆通过持久化检查的比例为 84.2%，完整 Write—Execute 攻击链成功率为 50.3%；在成功投毒条件下，选择性修复率为 56.1%。主要攻击收缩发生在模型是否采纳记忆（76.1% 降至 53.7%），主要修复失败来自删除恶意内容时破坏良性记忆。两名人工标注与裁判模型在 500 条样本上的一致率分别为 90.60% 和 91.80%。
- **局限与风险**：这是尚未经过同行评审的预印本；每个配置—案例只运行一次，结果是描述性比较而非稳定排名。任务为英语案例，配置仅覆盖 OpenClaw、Hermes、四种后端和三个模型；裁判模型约 9% 的不一致也会影响检查点统计。作者明确指出不存在对所有框架都更安全的单一后端。
- **实践关系**：记忆产品的安全回归测试需要同时报告写入、召回、采纳、外部后果、恶意语义移除和良性语义保留，不能用单点拒绝率或“一键清空”代表安全。后端、检索阈值、元数据和智能体框架应作为完整系统共同评估。
- **推荐理由**：该基准把记忆投毒从单轮成功率扩展为可审计的生命周期，并清楚展示“抗攻击”和“能修复”是两个独立目标。
