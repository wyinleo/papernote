### 1. Confundo: Learning to Generate Robust Poison for Practical RAG Systems

- **方向**：人工智能安全 / RAG 投毒
- **关键词**：RAG、检索投毒、黑盒攻击、鲁棒性
- **名词解释**：
  - **RAG**：先从外部语料检索相关材料，再让大模型依据材料回答问题的生成方式。
  - **检索投毒**：向语料库加入经过设计的内容，使它被特定查询检索到并影响最终回答。
- **单位与作者**：
  - 香港大學：Haoyang Hu、Zhejun Jiang、Junyuan Zhang、Ka-Ho Chow
  - 南京大学：Yueming Lyu
  - 香港城市大學：Yi Liu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/hu-haoyang)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-hu-haoyang.pdf)
- **核心问题**：已有 RAG 投毒往往依赖冗长、脆弱或特定检索器的文本；论文研究能否在不了解目标生成模型的条件下，生成更短且能跨分块、改写和检索器迁移的毒化文档。
- **方法与贡献**：Confundo 微调 Qwen3-0.6B 作为毒文本生成器，以三个检索器组成的集成反馈优化检索命中和目标语义，并在训练中加入分块与词汇变化。攻击覆盖事实篡改、观点操纵和诱发幻觉。
- **方法示例**：攻击者只插入约 31 词的短段落，使关于《Harry Potter》的 RAG 在多个分块策略下持续返回错误事实；即使系统改写查询或更换生成模型，毒段仍可能被检索并主导回答。
- **实验与证据**：事实篡改攻击成功率为 88%，高于 AuthChain 的 54%，平均长度 30.69 词而非 114.65 词；查询改写仅使成功率下降 7 个百分点。跨 RAG 框架为 88%—89%，迁移到未知生成模型为 81%—93%；意图检测防御把 88% 降到 57%，仍有明显残余风险。
- **局限与风险**：评估基于实验性 RAG 配置与公开数据集，不能代表所有生产检索、访问控制和数据治理；生成器本身具有双重用途，结果也不证明任何被检索文档都能稳定控制回答。
- **实践关系**：RAG 防护应同时覆盖入库来源、语义异常、跨检索器一致性和回答溯源；仅靠查询改写或单个意图分类器不足以形成可靠边界。
- **推荐理由**：它把投毒从“能命中”推进到短文本、跨组件和抗改写的实际约束，并给出对现有防御残余风险的直接测量。

### 2. Context Contamination in LLM Analysis of Network Security Logs: Poison with Passive Prompt Injection and Mitigation Evaluation

- **方向**：人工智能安全 / 安全运营
- **关键词**：安全日志、被动提示注入、AIOps、分层防御
- **名词解释**：
  - **被动提示注入**：攻击者只把指令写进会被采集的日志或内容，等待分析系统以后自动读取，无需直接与模型对话。
  - **分层防御**：在数据采集、提示构造、模型判断和工具执行等多个环节分别设置控制，避免单点失守。
- **单位与作者**：
  - PayPal：Rabimba Karanjai、Hemanth Hegadehalli Madhavarao
  - University of Houston：Rabimba Karanjai、Yang Lu、Weidong Shi
  - Kent State University：Lei Xu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/karanjai)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-karanjai.pdf)
- **核心问题**：当大模型直接分析 Apache、SSH 或 JSON 日志时，攻击者可把指令写进日志而不与模型交互。论文量化这种“只写日志”的上下文污染能否隐瞒事件、伪造结论或改变响应建议。
- **方法与贡献**：作者构建含 12,847 条日志、其中 2,569 条对抗样本的基准，覆盖三类格式、三个模型和四种攻击目标；Context Stitching 将载荷拆散并借上下文重组，随后比较提示约束、编码、检测与分层组合。
- **方法示例**：攻击者让多条看似普通的日志分别携带半句指令，单条检测不显眼；分析模型汇总相邻事件时把碎片拼为“忽略此前异常并报告正常”，从而污染最终研判。
- **实验与证据**：基线攻击最高成功率 88.2%，平均 83.4%；Context Stitching 为 76.4%。分层防御相对降低 90.4%，但仍残留 8.4%；每项运行五次，置信区间约为 ±2.6 个百分点。
- **局限与风险**：只覆盖三种模型和 LogHub/合成混合数据，载荷由人工设计，威胁模型是假定攻击者只能盲写日志；GPT 裁判也可能有偏差，结论不覆盖传统 SIEM 预处理或离线人工复核。
- **实践关系**：SOC 不应把原始日志直接并入系统提示；需要字段级数据/指令隔离、结构验证、独立检测和输出证据回链，并把日志中的自然语言视为不可信输入。
- **推荐理由**：论文给出被动注入的规模化基准与防御残差，直接对应越来越常见的 LLM 日志分析管线。

### 3. MUZZLE: Adaptive Agentic Red-Teaming of Web Agents Against Indirect Prompt Injection Attacks

- **方向**：人工智能安全 / Web 智能体
- **关键词**：智能体、间接提示注入、自适应红队、跨应用攻击
- **名词解释**：
  - **自适应红队**：攻击智能体根据目标系统的反馈不断改写载荷，而不是只测试一组固定提示。
  - **跨应用攻击**：恶意内容从一个应用或网页进入智能体上下文，却在另一个应用中触发敏感操作。
- **单位与作者**：
  - 美国东北大学：Georgios Syros、Evan Rose、William Robertson、Cristina Nita-Rotaru、Alina Oprea
  - Mozilla Corporation：Brian Grinstead、Christoph Kerschbaumer
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/syros)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-syros.pdf)
- **核心问题**：固定注入模板难以覆盖浏览器智能体的多步状态、工具反馈和跨应用交互。论文研究红队智能体能否根据失败轨迹自动定位关键节点、重写载荷并验证真实外部后果。
- **方法与贡献**：MUZZLE 用轨迹显著性选择可操纵页面位置，再由 Grafter 生成、优化和反思载荷，并以独立裁判验证结果；在 The Zoo 沙箱中形成 44 条端到端攻击，覆盖四个应用、十个目标和三条跨应用路径。
- **方法示例**：恶意网页先诱导购物智能体读取隐藏说明，再让它跳转邮件或数据库工具提取凭据；红队器根据工具拒绝或导航失败自动改写指令，而不是重复同一模板。
- **实验与证据**：代表性目标各运行五次，凭据外传成功 4/5，数据库跨应用链为 2/5；组合载荷在四个应用的十次重复中总体成功率 86.7%，WASP 固定模板为 20%。模型与智能体脚手架都会显著改变是否完整执行攻击链。
- **局限与风险**：实验只覆盖四个沙箱应用和三种受测模型，攻击生成依赖 GPT-4o/4-turbo 且推理成本较高；结果不是对真实在线服务、授权弹窗和企业访问控制的普遍成功率。
- **实践关系**：智能体红队应按工具轨迹和外部状态判定成功，并覆盖跨应用链；防守方则需在每次工具调用重新验证来源、权限与用户意图。
- **推荐理由**：它把提示注入红队从静态字符串扩展为会观察失败、调整策略并验证后果的完整测试过程。

### 4. AttriGuard: Defeating Indirect Prompt Injection in LLM Agents via Causal Attribution of Tool Invocations

- **方向**：人工智能安全 / 智能体工具安全
- **关键词**：间接提示注入、因果归因、工具调用、运行时防御
- **名词解释**：
  - **因果归因**：判断某次工具调用究竟由用户目标还是外部不可信内容导致，而不只检查文本是否可疑。
  - **工具调用**：模型向浏览器、文件系统或 API 发出的结构化操作请求，是智能体产生现实后果的关键边界。
- **单位与作者**：
  - 浙江大学：Yu He、Haozhe Zhu、Shuo Shao、Zhihao Liu、Zhan Qin
  - Nanyang Technological University：Yiming Li
  - 香港城市大學：Hongwei Yao
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/he-yu)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-he-yu.pdf)
- **核心问题**：智能体读取不可信页面后，如何判断某个高风险工具调用究竟由用户目标还是注入文本促成，同时避免静态权限系统过度阻断正常任务。
- **方法与贡献**：AttriGuard 对候选动作执行 teacher-forced shadow replay，逐层削弱可疑上下文并观察动作是否仍存活，以动作级因果归因定位驱动来源；层次化控制和模糊存活判定降低额外调用与误拦截。
- **方法示例**：邮件中的隐藏指令要求把文件发给外部联系人。系统分别重放“保留用户任务、移除邮件指令”等上下文；若发送动作只在恶意内容存在时出现，就在工具执行前阻断，而不是把整封邮件或所有发送能力一律禁用。
- **实验与证据**：在四种大模型及 AgentDojo 等任务上，静态攻击对十种防御配置的攻击成功率均为 0%，总体效用损失很小；在 200 次评估预算的遗传算法和 OpenEvolve 自适应攻击下仍保持韧性。CaMeL 同样能归零攻击，但正常任务效用更低。
- **局限与风险**：长链和工具密集任务会增加误判，Llama Travel 场景的效用下降约 20%；结果依赖辅助模型和工具 schema，对委托型任务、仅代码参数及更强自适应攻击仍需验证，也会引入额外推理开销。
- **实践关系**：高风险工具调用可在执行前加入动作级来源证明，把“不可信内容参与了推理”与“它因果驱动了动作”区分开；仍应结合最小权限和用户确认。
- **推荐理由**：防御目标从文本检测转向工具行为的因果来源，更贴近智能体真正造成损害的边界。

### 5. Cloud-Native Carjacking: Fleet-wide Compromise via Telematics Authorization Failures

- **方向**：移动与物联网安全 / 车联网
- **关键词**：车联网、云端授权、车辆身份、远程控制
- **名词解释**：
  - **车联网遥测平台**：接收车辆状态并向车辆下发远程命令的云服务。
  - **授权失败**：服务已识别请求者身份，却没有正确检查其是否有权控制指定车辆或整个车队。
- **单位与作者**：
  - 香港理工大学：Yangyang Liu、Xiapu Luo
  - 吉利汽车研究院：Zhengjie Du、Yang Yin
  - 吉利学院：Xiaofang Wang
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/liu-yangyang)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-liu-yangyang.pdf)
- **核心问题**：车辆云服务常把设备认证材料与具体 VIN 或逻辑车辆身份分开处理。论文检验攻击者从一辆种子车辆取得合法凭据后，能否跨车辆复用云端会话并越权控制车队。
- **方法与贡献**：作者分析 MQTT、HTTPS 和短信后备协议，从量产车进程内存恢复认证材料，建立合法会话后系统修改 VIN 与逻辑 ID，定位身份认证与对象授权脱节，并与三家车企协调修复。
- **方法示例**：种子车辆的客户端证书能建立 MQTT 会话，但后端又相信消息中的目标车辆标识；攻击者替换标识后，可让同一认证主体请求另一辆车的指令或隐私数据。
- **实验与证据**：研究在三家车企的五辆量产车上验证，发现可跨车辆远程解锁、访问私密监控数据和伪造后备指令的授权失败；厂商确认问题并部署缓解。测试在受控环境进行，没有影响真实用户。
- **局限与风险**：样本是五辆车和若干传统平台，不能外推全部车云架构；初始阶段需要对种子车辆取得物理或特权访问，后续能力还受网络、车型和厂商配置约束。
- **实践关系**：车云后端必须把证书、设备、VIN、租户和每条命令做不可绕过的服务端绑定，并对跨对象请求进行持续审计；设备认证不能替代对象级授权。
- **推荐理由**：它用真实量产车证明一次设备凭据泄漏如何被云端授权缺陷放大为车队级风险。

### 6. When Authorization Loses Its Meaning: Breaking and Fixing Third-Party Online Payments

- **方向**：身份与隐私 / 支付授权
- **关键词**：第三方支付、授权语义、Android、形式化验证
- **名词解释**：
  - **授权语义**：用户确认的金额、收款方和订单，与协议最终执行的支付动作必须保持同一含义。
  - **形式化验证**：用数学模型描述协议状态和安全目标，并系统检查是否存在违反目标的执行路径。
- **单位与作者**：
  - 武汉大学国家网络安全学院：Yongkang Xiao、Jing Chen、Min Shi、Kun He、Qiyi Deng、Ruiying Du
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/xiao)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-xiao.pdf)
- **核心问题**：第三方支付在商户、应用、用户和支付服务商之间传递订单时，界面上“用户已授权”的语义可能没有密码学绑定到最终订单。论文寻找客户端劫持、订单替换和跨场景授权混淆。
- **方法与贡献**：作者对两个支付服务商的六种协议和三类场景建立 Tamarin 模型，在弱化信道假设下推导攻击；随后实现 Android 隐式 Intent 劫持，并提出由用户侧对订单做签名/认证的修复协议并形式化验证。
- **方法示例**：恶意应用截获商户发往支付应用的隐式 Intent，替换金额或收款方，再把看似正常的结果返回商户；用户看到的确认与商户最终接受的订单没有同一份不可伪造绑定。
- **实验与证据**：作者分析 461 个 Android 应用，超过四分之一存在可利用路径，相关应用累计下载量超过 2000 亿；形式化模型复现授权缺口，并验证用户侧订单认证在给定威胁模型下满足目标性质。
- **局限与风险**：修复需要新增密钥、签名和安全存储，并要求初次建立信任；TOFU 不能改善第一次付款。实证集中在两个中国支付服务生态，下载量不是实际受害规模。
- **实践关系**：支付应用应使用显式组件、绑定订单摘要与回调主体，并让用户确认的金额、商户和最终结算对象共享可验证凭据；平台还应淘汰可被任意应用接收的支付 Intent。
- **推荐理由**：论文把“界面确认不等于协议授权”同时落到形式化证明、真实应用测量和可部署修复。

### 7. WILD Attack: Stealthy Undermining of Wi-Fi-Based Geolocation Through Remote Crowdsourced Data Injection

- **方向**：网络与通信安全 / Wi-Fi 定位
- **关键词**：Wi-Fi 定位、众包数据、位置操纵、数据完整性
- **名词解释**：
  - **Wi-Fi 众包定位**：手机上报接入点标识和观测位置，平台汇总后用附近 Wi-Fi 推断设备位置。
  - **远程数据注入**：攻击者无需接近目标接入点，也能向众包数据库提交伪造位置观测。
- **单位与作者**：
  - University of South Florida：Changjia Zhu、Xiao Han、Parush Gera、Zhuo Lu、Tempestt Neal、Yao Liu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/zhu-changjia)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-zhu-changjia.pdf)
- **核心问题**：Wi-Fi 定位服务依赖手机上报 BSSID 与位置。论文研究攻击者能否不接近目标 AP，只在远程广播目标标识并众包虚假位置，进而改写全球定位数据库。
- **方法与贡献**：WILD 对 Google、Apple、A-Map 与 WiGLE 的更新策略进行受控测量，构造远程 BSSID 重放和多设备众包流程，并研究条目新增、迁移、删除及持续时间。
- **方法示例**：攻击者在另一城市让设备广播目标路由器的 BSSID，再让多台手机同时提交本地 GPS；数据库若信任近期多数报告，就可能把真实路由器“搬到”攻击者选择的位置。
- **实验与证据**：四个服务的受控实验表明条目可被植入、迁移或移除，部分错误位置持续数周；论文给出三个案例，并遵循伦理约束，没有影响真实用户。
- **局限与风险**：平台策略会随时间变化，攻击需要获得目标 BSSID并控制广播和上报设备；成功率与持续性高度依赖服务商，受控案例不等于大规模真实滥用。
- **实践关系**：定位平台需要对远距离突变、多设备相关性和 BSSID 复制做异常检测，以历史轨迹、硬件证明或跨传感器证据约束众包更新。
- **推荐理由**：它揭示远程数据投毒可把本地无线标识变成全球位置完整性问题，并提供跨平台实测。

### 8. SafeFFI: Efficient Sanitization at the Boundary Between Safe and Unsafe Code in Rust and Mixed-Language Applications

- **方向**：软件与应用安全 / 内存安全
- **关键词**：Rust、FFI、sanitizer、边界检查
- **名词解释**：
  - **FFI**：让 Rust 与 C/C++ 等其他语言互相调用的接口，跨越后 Rust 的类型和内存保证可能不再成立。
  - **Sanitizer**：在运行时插入检查、发现越界或非法指针等错误的动态检测工具。
- **单位与作者**：
  - Ludwig-Maximilians-Universität München：Oliver Braunsdorf、Tim Lange、Johannes Kinder
  - Fraunhofer AISEC：Konrad Hohentanner、Julian Horsch
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/braunsdorf)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-braunsdorf.pdf)
- **核心问题**：Rust 的安全代码仍可能通过 FFI 接收来自 C/C++ 的无效指针；全程序 ASan/HWASan 成本高，而只检查 unsafe 块又可能漏掉随后在 safe 代码中的解引用。
- **方法与贡献**：SafeFFI 把 sanitizer 检查移动并合并到原始指针转换为安全引用的边界，以函数内数据流推导必要范围；这样保留对跨语言内存错误的检测，同时删除安全区域内重复检查。
- **方法示例**：C 库返回缓冲区指针，Rust wrapper 把它转换为 slice。SafeFFI 在这次转换验证地址和长度，之后 safe Rust 访问无需逐次插桩；若长度伪造或指针已释放，错误在边界被捕获。
- **实验与证据**：在 Rust crates 和真实漏洞集上，检查数量减少 72.02%—79.63%；ASan 平均开销从 2.71 倍降到 2.44 倍，HWASan 从 3.18 倍降到 2.29 倍，编译开销 2.01 倍而此前方案超过 5.91 倍。它检测到相同的 sanitizer 可见漏洞，其中 21 个更早暴露。
- **局限与风险**：多线程中引用存活期间被另一线程释放仍可能形成竞态；内联汇编、`transmute` 等非常规转换可能造成漏报。实现基于 Rust 1.52/LLVM 12，需在现代工具链复核。
- **实践关系**：混合语言项目可把 FFI wrapper 作为可审计安全关口，以较低成本在 CI 和预发布测试启用 sanitizer；这不替代所有权设计、线程同步和 C 端修复。
- **推荐理由**：它为“安全语言边界仍需动态检查”给出清晰的插桩位置和实测性能收益。

### 9. FRAGJAM: DoS Attacks Using IP Reassembly Congestion

- **方向**：网络与通信安全 / IP 分片
- **关键词**：IP 分片、NAT、资源耗尽、拒绝服务
- **名词解释**：
  - **IP 重组**：接收端把多个 IP 分片按标识和偏移重新拼成原始数据包的过程。
  - **NAT**：在内外网络之间改写地址和端口的设备；它保存的分片与连接状态也可能成为耗尽目标。
- **单位与作者**：
  - CISPA Helmholtz Center for Information Security：Yepeng Pan、Christian Rossow
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/pan)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-pan.pdf)
- **核心问题**：Linux NAT 的 IP 重组队列是共享有限资源。论文研究离路径攻击者能否先诱导服务器分片，再用伪造碎片占满 NAT 重组缓存，使正常长连接持续丢包或降级。
- **方法与贡献**：FRAGJAM 组合伪造 ICMP Packet Too Big 与低带宽碎片注入：前者让服务器缩小 PMTU 并主动分片，后者制造永不完成的重组项；作者分析内核资源策略并在视频会议、RADIUS 和 VPN 中实现端到端攻击。
- **方法示例**：攻击者伪造一条看似来自路径的 PTB，让 Zoom 流量开始分片；再向同一 NAT 注入缺少尾片的碎片组，占满全局重组阈值，合法视频分片到达时被丢弃。
- **实验与证据**：本地与模拟网络中，攻击影响 Zoom、Webex、RADIUS，以及 ExpressVPN、Proton 等服务，造成断流、重连或安全降级；研究向相关厂商和维护者披露并讨论内核缓解。
- **局限与风险**：攻击要求源地址伪造和离路径报文可达，目标需使用受影响的 Linux NAT，服务器还需接受伪造 PTB 并产生分片；应用后备行为各异，结论不是对所有 NAT 或服务的普遍 DoS。
- **实践关系**：网络边界应过滤伪造源、验证 PTB、限制每源重组资源并监控异常不完整碎片；服务端应避免无验证地长期缓存可疑 PMTU 下降。
- **推荐理由**：论文把两个常被分别看待的机制——PMTU 与 NAT 重组——拼成低交互、跨应用的资源耗尽链。

### 10. WAVED: Principled Identification of Off-Path Exploitable Weak Verifications within the TCP/IP Protocol Suite

- **方向**：网络与通信安全 / TCP/IP 实现
- **关键词**：离路径攻击、弱验证、静态分析、污点分析
- **名词解释**：
  - **离路径攻击**：攻击者不能直接看到双方流量，只能猜测并注入伪造数据包。
  - **弱验证**：实现只检查了本应同时满足的若干字段中的一部分，使猜中的概率显著升高。
- **单位与作者**：
  - 清华大学：Yizhou Zhao、Xuewei Feng、Ke Xu
  - 中关村实验室：Min Li、Ke Xu
- **出处与状态**：USENIX Security 2026｜接收
- **公开或更新时间**：2026-08-12 正式公开（本期基线补录）
- **原文链接**：[USENIX 官方页面](https://www.usenix.org/conference/usenixsecurity26/presentation/zhao-yizhou)、[正式论文集 PDF](https://www.usenix.org/system/files/usenixsecurity26-zhao-yizhou.pdf)
- **核心问题**：TCP/IP 栈会检查序号、地址和协议字段，但某些路径只验证其中一部分，允许离路径伪造包改变连接状态。人工审计难以跨 IPv4/IPv6 和多个内核系统发现这类“验证存在但强度不足”的语义漏洞。
- **方法与贡献**：WAVED 在 LLVM/SVF 上构建流、上下文和字段敏感的指针分析与字节级污点传播图，再按报文方向比较约束强度，定位外部字段进入敏感状态前缺失或不对称的验证。
- **方法示例**：接收路径只检查伪造 ICMP 引用包的目标地址，却没有充分约束内部 TCP 序号；WAVED 比较字段来源与约束后标出该弱验证，攻击者可猜测更少状态并诱导连接重置或降级。
- **实验与证据**：对 Linux 5.15/6.8、FreeBSD 14.1 的 IPv4/IPv6 实现分析发现 19 个弱验证漏洞，其中 14 个此前未知；作者结合概念验证和披露验证其安全影响。
- **局限与风险**：静态污点分析无法完全建模运行时状态，仍会产生误报；当前只编码两类高风险语义模式且不覆盖隧道协议。实际利用通常还依赖 IP 欺骗可达性或缺失入口过滤。
- **实践关系**：协议栈审计应比较相邻路径和报文方向的验证强度，而不只搜索完全缺失的检查；运营侧应落实 BCP 38 等源地址过滤，降低离路径攻击前提。
- **推荐理由**：它把协议语义中的“检查得不够强”转化为可扩展静态分析问题，并在两个主流内核中发现大量新缺陷。
