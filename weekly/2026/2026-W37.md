### 1. Leafblower: a Leakage Attack Against TEE-Based Encrypted Databases

- **方向**：系统与硬件安全 / TEE 加密数据库
- **关键词**：机密计算、B+ 树、结构泄漏、多快照攻击
- **名词解释**：
  - **多快照攻击者**：不能读取明文，只能反复比较加密文件在每次操作后哪些页发生变化的观察者。
  - **结构泄漏**：密文虽然隐藏内容，页分裂、节点更新等数据结构形状仍会暴露值之间的顺序关系。
- **单位与作者**：
  - Brown University：Seny Kamara
  - MongoDB Research：Zachary Espiritu、Seny Kamara、Tarik Moataz
  - NetApp：Valentin Ogier
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00008)、[作者全文](https://zacharyespiritu.com/papers/leafblower-sp2026.pdf)
- **核心问题**：现有数据库可以借 LibOS 直接搬进 TEE，并加密磁盘索引，但这种“lift-and-shift”是否真的隐藏了查询与插入值仍缺少系统分析。论文聚焦持久化 B+ 树在每次操作后写回页的模式。
- **方法与贡献**：Leafblower 先从相邻密文快照恢复每次操作修改的页集合，再利用 B+ 树节点分裂和共同更新关系推断叶节点顺序，最后把外部辅助分布与该顺序对齐，恢复插入值。
- **方法示例**：观察者看不到三次插入的键，却发现第一次和第三次修改同一叶页、第二次触发相邻页分裂；累积更多快照后可排序三次插入，再用公开人口或时间分布把顺序映射回近似明文。
- **实验与证据**：在最有利的准确辅助信息和小值域条件下，真实数据实验可精确恢复最高 96% 的插入值；恢复出稳定叶序后，后续插入的相对顺序可达到 100%。攻击不需要向数据库注入查询，也不依赖读取查询结果。
- **局限与风险**：结果随辅助数据误差、值域扩大、重复值、批处理和页布局变化下降；威胁模型要求持续取得操作级磁盘快照。论文证明的是特定持久化索引泄漏，不能外推为所有 TEE 数据库都可同样恢复。
- **实践关系**：在 TEE 内运行数据库仍应隐藏访问模式，至少评估写回合并、页重排、ORAM 或索引专用保护；磁盘快照、备份和增量复制权限也应视作敏感观测面。
- **推荐理由**：它以弱于内存总线观察的攻击者击穿常见部署模式，说明“数据使用时加密”不能自动消除数据结构元数据。

### 2. The Threat Landscape of IP Leasing in the RPKI Era

- **方向**：网络与通信安全 / RPKI 与 IPv4 租赁
- **关键词**：RPKI、IP 租赁、路由劫持、互联网测量
- **名词解释**：
  - **ROA**：由地址前缀权威签发、声明哪些自治系统可以起源该前缀的 RPKI 对象。
  - **依赖方（RP）**：下载并验证 RPKI 仓库、把结果提供给路由器做起源验证的系统。
- **单位与作者**：
  - Virginia Tech：Weitong Li、Yongzhe Xu、Taejoong Chung
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00012)、[作者全文](https://weitongli.com/publications/papers/li-2026-hijack.pdf)
- **核心问题**：短期 IPv4 租赁把实际使用权交给承租方，但 RIR 与 RPKI 仍把出租方视作密码学权威。恶意出租方因此可能在合同有效期内撤销或分裂 ROA 视图，使承租方流量被丢弃或重定向。
- **方法与贡献**：论文测量租赁生态，构造“对少数 RP 展示合规 ROA、对其余互联网展示恶意 ROA”的选择性发布攻击，并提出多 RP 交叉验证、中立经纪方托管 ROA 以及 RIR 门户部分授权三类缓解。
- **方法示例**：出租方让承租方自己的监测 RP 继续看到合法起源，却向其他地区发布使该起源 invalid 的 ROA，再由攻击者宣告替代路线；承租方本地仪表盘看似正常，外部流量却已改道。
- **实验与证据**：测量发现超过 44,000 个活跃租赁前缀，承载政府、金融、网站、DNS 与 NTP 服务；在两家大型云平台和跨洲 PEERING 测试床上，攻击可重路由租赁前缀，并演示 TLS 证书验证截获和区域性劫持。
- **局限与风险**：租赁识别依赖公开路由、注册和服务信号，可能漏报或误归因；测试床和自有前缀实验不能完全复刻所有运营商策略。恶意出租方是否实际实施攻击仍需事件证据，合同救济也因辖区而异。
- **实践关系**：承租方不应只监控单一 RP 或本地 BGP 视图；采购合同应明确 ROA 控制、变更审计和应急转移，并推动 RIR 支持可撤销、可限期的授权委托。
- **推荐理由**：它把地址短缺催生的商业实践与路由安全的根信任直接对照，暴露了“法律使用权不等于技术控制权”。

### 3. Fine-Grained Kernel Auditing using Augmented Syscall Reference Behavior Analysis and Virtualized Selective Tracing

- **方向**：系统与硬件安全 / 内核取证
- **关键词**：Linux 内核、系统调用、控制流审计、硬件追踪
- **名词解释**：
  - **参考行为**：一个系统调用在正常情况下可能经过的内核函数集合，用来区分罕见但合法路径与攻击偏转。
  - **选择性追踪**：只记录被判定为异常或低概率的控制流，而非保存所有内核函数执行。
- **单位与作者**：
  - National University of Singapore：Chuqi Zhang、Zhenkai Liang
  - Arizona State University：Spencer Faith、Feras Al-Qassas、Theodorus Februanto、Adil Ahmad
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00013)、[作者全文](https://www.chuqiz.com/papers/appare_paper.pdf)
- **核心问题**：传统审计只记录 syscall 入口和用户态事件，内核利用在单次系统调用内部劫持了哪些函数、获得什么能力通常不可见；全量控制流追踪又产生不可接受的运行与存储成本。
- **方法与贡献**：APPARE 用代表性负载做动态剖析，再用带 RAG 上下文的 LLM 语义判断补足静态可达但动态未见的正常路径；运行时由虚拟化监控器和硬件追踪只记录偏离参考行为的控制流，并保护日志免受已失陷内核篡改。
- **方法示例**：CVE-2021-22555 在普通 `write`/`close` 内跳入凭据操纵函数。常规日志只看见例行系统调用，APPARE 则把这些不在参考集合中的函数和此前控制流上下文写入取证日志。
- **实验与证据**：参考集合只覆盖全部内核函数的 0.01%—7.11%，平均比朴素方案小 75.1%；LLM 语义验证准确率为 83.7%，去掉 RAG 时为 69.7%。系统捕获所测真实利用的控制流，跨工作负载开销 0.2%—6.8%，几何平均 2.0%。
- **局限与风险**：原型依赖特定虚拟化与 Processor Trace 能力，LLM 判断可能漏掉合法稀有路径或错误扩张集合；当前追踪与压缩在内存密集负载上仍可能受 VM exit 成本影响，且语义模型不能代替完整安全证明。
- **实践关系**：适合高价值 Linux 工作负载作为现有 syscall 审计的细粒度补层；上线前必须用本地内核版本和负载重新生成参考集，并把异常日志与镜像、符号和事件时间线一并保全。
- **推荐理由**：论文同时解决“看得见内核利用”和“日志成本可控”，并量化了 LLM 增广真正带来的参考集准确率收益。

### 4. Defeating Transient Execution Attacks by Limiting Secret Reachability through Register Hiding and ShadowCFI

- **方向**：系统与硬件安全 / 瞬态执行防御
- **关键词**：Spectre v2、秘密可达性、寄存器隐藏、控制流完整性
- **名词解释**：
  - **秘密可达性**：瞬态 gadget 能否从错误预测时保留的寄存器状态定位并读取目标秘密。
  - **ShadowCFI**：只允许在正确分支目标处恢复隐藏寄存器状态的影子控制流完整性机制。
- **单位与作者**：
  - MIT CSAIL：Daniël Trujillo、Mengjia Yan
  - AMD：Jagadish Kotra、David Kaplan
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00015)、[作者全文](https://people.csail.mit.edu/mengjia/data/2026.SP.RegisterHiding.pdf)
- **核心问题**：Spectre v2 防御通常围绕特定预测器或攻击变体阻止误预测，却不断被新微架构路径绕过。作者指出所有这类攻击还共享一个更基础条件：gadget 需要借提交前的寄存器状态找到秘密。
- **方法与贡献**：Register Hiding 在潜在危险间接分支前清空通用寄存器，把原状态移入隐藏存储；ShadowCFI 只在架构上正确的目标恢复状态。作者实现 Linux 6.8 补丁、形式化安全目标与扫描器，覆盖间接跳转、调用和返回。
- **方法示例**：若误预测跳到一个“按寄存器地址读取并编码缓存”的 gadget，寄存器已被清空，gadget 即使执行也找不到秘密；只有真实目标通过 ShadowCFI 检查后才能恢复参数。
- **实验与证据**：在 AMD Zen 4 上，以 Register Hiding + ShadowCFI 替换最新 Spectre v2 缓解后，LEBench 总缓解开销从 114.1% 降至 75.9%，服务器负载平均从 33.4% 降至 25.8%；安全扫描验证 PoC 中不存在可在误预测路径恢复状态的序列。
- **局限与风险**：证明依赖明确的软件变换、隐藏存储语义和扫描器模型，未覆盖所有未来指令副作用或硬件缺陷；仍有显著性能成本，闭源内核模块、手写汇编及不同 ISA 需要单独适配。
- **实践关系**：为内核提供比“每出现一种 Spectre 就加一个预测器补丁”更统一的设计方向，但部署前必须结合真实服务器负载、汇编边界和供应商微码共同验证。
- **推荐理由**：它把防守目标从预测器细节上移到攻击必要条件，并给出能运行的内核实现和与现役缓解的直接成本比较。

### 5. APIEcho: Training-less Anomaly Detection via Intra-API Behavioral Comparison for Web Applications

- **方向**：软件与应用安全 / Web 入侵检测
- **关键词**：API 行为、无训练异常检测、系统调用、抗投毒
- **名词解释**：
  - **API 内比较**：只比较同一个 API 的多次请求，避免不同功能天然不同的系统调用被误判为异常。
  - **滑动窗口**：只保留最近一段行为作为动态参照，并逐步丢弃旧事件。
- **单位与作者**：
  - 清华大学：Yihao Peng、Yiming Wu、Du Wu、Hai Wan、Xibin Zhao
  - 浙江大学：Shouling Ji
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00016)、[作者全文](https://xy20130630.github.io/files/apiecho.pdf)
- **核心问题**：规则无法覆盖未知攻击，学习模型又需要干净训练集并在应用更新后重训；此前“副本间比较”还假设同一服务副本应行为一致，但现代单体和微服务 API 内部差异很大。
- **方法与贡献**：APIEcho 动态识别 API，把请求分到对应窗口，提取顺序、状态和参数相关系统调用特征，再做同 API 内相似度比较；自适应阈值处理行为多样性，抗投毒更新只让可信正常单元进入基线。
- **方法示例**：搜索 API 的不同关键词可以产生不同文件访问，但仍共享稳定阶段结构；利用请求新增异常 shell 与网络序列时，会偏离该 API 最近正常窗口，而不会与登录或上传 API 混比。
- **实验与证据**：16 个真实 Web 应用场景中，攻击召回率超过 90%、正常事件准确率高于 99%；渐进投毒实验仍保持 99.9% 正常准确率。默认窗口 100 时吞吐约 12,041 条日志事件/秒，内存随窗口扩大后趋于平台期。
- **局限与风险**：依赖审计日志完整且不被攻击者篡改；非常多态的 API、并发异步行为或同一窗口内多数请求同时被攻陷会削弱参照。动态 API 分类错误虽在实验中影响较小，生产路由变化仍需监控。
- **实践关系**：可作为规则和训练型检测的补充，特别适合频繁发布的 Web 服务；需要把 API 目录、窗口污染告警与发布事件关联，并在日志源外建立完整性保护。
- **推荐理由**：它没有用“无需训练”回避基线污染和应用更新，而是通过 API 粒度、阈值和窗口机制逐项验证这些问题。

### 6. SmuFuzz: Enable Deep System Management Mode Fuzzing in Fully Featured UEFI Runtime Environment

- **方向**：系统与硬件安全 / UEFI 固件模糊测试
- **关键词**：UEFI、SMM、重托管、固件模糊测试
- **名词解释**：
  - **SMM**：x86 上比操作系统内核权限更高的系统管理模式，厂商固件用它处理电源、硬件与安全任务。
  - **部分重托管**：不模拟整台机器，只把目标固件及其必要运行环境搬到可观测、可快照的执行框架中。
- **单位与作者**：
  - CISPA Helmholtz Center for Information Security：Jianqiang Wang、Meng Wang、Ali Abbasi
  - 浙江大学：Yi Xiang、Qinying Wang
  - EPFL：Yi Xiang、Qinying Wang
  - Max Planck Institute for Security and Privacy：Thorsten Holz
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00011)、[作者全文](https://raw.githubusercontent.com/wjqsec/smufuzz/main/smufuzz.pdf)、[项目](https://github.com/wjqsec/smufuzz)
- **核心问题**：闭源 SMM 应用依赖完整 UEFI 初始化、协议和设备状态，现有重托管常在未初始化数据处提前退出或崩溃，只覆盖浅层路径并产生大量假阳性。
- **方法与贡献**：SmuFuzz 构造可运行的 UEFI/SMM 环境，按依赖递归加载模块，并在初始化与处理阶段分别使用约束和模糊输入；它自动推断通信缓冲区、寄存器、端口 I/O 等输入语义，并用快照与内存拦截加速深层探索。
- **方法示例**：某 SMI handler 依赖厂商核心服务模块写入协议表；旧工具没加载该模块便在入口退出，SmuFuzz 先完成依赖初始化，再把攻击者控制的嵌套指针重定向为 fuzz 数据，继续探索深层内存访问。
- **实验与证据**：在 9 个品牌的 31 个 UEFI 固件上各重复五次、运行 24 小时；除一个不支持的非位置无关样本外，基本块覆盖平均为 RSFUZZER 的 4.45 倍。SmuFuzz 报告 177 个真实漏洞、正确率 73.12%，对比 efiXplorer 的 19/1.13% 和 RSFUZZER 的 59/10.35%；其中确认 38 个此前未知漏洞并负责任披露。
- **局限与风险**：一个非位置无关固件不受支持；递归依赖加载失败仍会漏掉 handler，当前 sanitizer 主要覆盖会崩溃的错误和堆越界，use-after-free、双重释放与栈溢出等仍可能漏检。真实固件没有完整漏洞真值。
- **实践关系**：固件厂商可在发布流水线中结合真实板卡回放和 SmuFuzz 长时任务，优先复查能由外部输入控制的崩溃；不能把“未发现”当作 SMM 安全证明。
- **推荐理由**：论文把固件 fuzzing 最棘手的初始化环境建模变成主要贡献，并用漏洞正确率而不只覆盖率证明收益。

### 7. WebCloak: Characterizing and Mitigating Threats from LLM-Driven Web Agents as Intelligent Scrapers

- **方向**：人工智能安全 / LLM 网页代理抓取
- **关键词**：网页智能体、内容抓取、动态混淆、语义迷宫
- **名词解释**：
  - **LLMCrawlBench**：面向网页图片资产抓取的可复现实验集，覆盖真实站点、图片和多类智能抓取器。
  - **语义迷宫**：向代理可读上下文加入无害但误导的线索，使中央 LLM 偏离真正资产，同时不改变用户看到的内容。
- **单位与作者**：
  - Nanyang Technological University：Xinfeng Li、Tianze Qiu、Lixu Wang、Xiaojun Jia、XiaoFeng Wang、Wei Dong
  - 香港理工大学：Yingbin Jin
  - University of Hawaiʻi at Mānoa：Hanqing Guo
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00025)、[作者全文](https://letterligo.netlify.app/paper/SP26_WebAgent.pdf)、[项目](https://web-cloak.github.io/)
- **核心问题**：多模态 LLM 让低门槛代理能理解页面并迭代修正抓取脚本，CAPTCHA、静态混淆和 User-Agent 规则容易失效；网站还需要在不破坏正常用户视觉体验的前提下降低自动提取成功率。
- **方法与贡献**：论文先构建 LLMCrawlBench，刻画 LLM-to-Script、纯 LLM 与 Web Agent 三类路径；WebCloak 再以客户端动态结构重排和视觉恢复隐藏真实资源结构，并用优化语义迷宫误导模型的页面解释。
- **方法示例**：用户仍看到正常商品图，但 DOM 中资源节点和恢复逻辑每次变化；代理根据旧结构生成脚本时得到诱饵或空结果，重新询问 LLM 又受到页面中无害语义线索干扰。
- **实验与证据**：基准含 50 个热门站点、5 类页面、237 个真实页面和 10,895 张图片，并评估 32 种抓取器实现。领先代理未防护时平均召回 88.7%，完整 WebCloak 降至 0%；知晓静态方案的自适应攻击可恢复到 52.3%，对动态方案仅约 0.22%。平均执行时间开销约 52 毫秒。
- **局限与风险**：客户端恢复代码最终仍可被高级对手分析，评估主要围绕图片，音频与文本只做较小补充；动态页面、无障碍工具、缓存和搜索索引兼容性需要站点逐一验证，防御也不能替代法律和访问控制。
- **实践关系**：适合高价值公开媒体资产作为速率限制、鉴权和水印之外的一层经济性防御；上线应持续做可访问性与跨浏览器回归，并假设对手会适配。
- **推荐理由**：它没有把普通 bot 防护直接套给智能体，而是先构建规模化代理基准，再用自适应对手验证动态防御的必要性。

### 8. Battering RAM: Low-Cost Interposer Attacks on Confidential Computing via Dynamic Memory Aliasing

- **方向**：系统与硬件安全 / 机密计算物理攻击
- **关键词**：DDR4 插板、动态地址别名、Scalable SGX、SEV-SNP
- **名词解释**：
  - **内存插板（interposer）**：插在 CPU 与 DIMM 信号路径之间、能够观察或改变地址/命令线的硬件。
  - **动态地址别名**：运行时改变地址线，使两个不同物理地址映射到同一内存位置，从而绕过启动时的一次性检查。
- **单位与作者**：
  - COSIC, KU Leuven：Jesse De Meulemeester、Ingrid Verbauwhede
  - University of Birmingham：David Oswald
  - Durham University：David Oswald
  - DistriNet, KU Leuven：Jo Van Bulck
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00052)、[作者全文](https://batteringram.eu/batteringram.pdf)、[项目](https://batteringram.eu/)
- **核心问题**：Intel 和 AMD 为软件制造的内存别名加入启动期固件检查，但这些机制是否能抵抗低成本、运行时切换地址线的物理攻击尚未验证。
- **方法与贡献**：作者用现成模拟开关和控制器构建低于 50 美元的 DDR4 插板，在检查结束后动态拉低地址位；攻击利用 Scalable SGX 的单密钥域实现任意明文读写并提取平台配置密钥，同时重新启用对最新 SEV-SNP 的完整证明绕过。
- **方法示例**：系统启动时插板透明直通，固件看不到别名；受保护工作负载运行后，攻击者切换 A11/A13 地址线，让攻击 enclave 的页与受害页重合，捕获或重放密文却由内存引擎按同一域解密。
- **实验与证据**：在三套 Intel/AMD DDR4 系统上验证，命令在默认 DRAM 频率下可 100% 准确重放且没有可辨识性能开销；端到端实验获得 Scalable SGX 任意明文访问和平台配置密钥，并在更新固件的 SEV-SNP 上复现证明攻击。器件成本比约 17 万美元的商用插板低数个数量级。
- **局限与风险**：攻击要求机箱和 DIMM 的物理访问；单个插板只能覆盖部分内存，需配合内存分配。DDR5 命令编码与校验更复杂，论文没有构建等价 DDR5 插板；TDX/CCA 部分结论主要来自设计分析而非完整实机攻击。
- **实践关系**：云与边缘机密计算的威胁模型必须明确是否排除硬件维护者；高保证部署需防拆、可信内存路径和运行时完整性/新鲜度，而不能只依赖启动期地址扫描。
- **推荐理由**：它把过去昂贵实验室级的内存信号攻击压到普通研究硬件成本，并直接击中远程证明的信任根。

### 9. GHost in the Shell: A GPU-to-Host Memory Attack and Its Mitigation

- **方向**：系统与硬件安全 / GPU 统一内存
- **关键词**：GPU、HMM、主机内存破坏、运行时隔离
- **名词解释**：
  - **HMM**：Linux 的异构内存管理，让 GPU 页故障和迁移机制可直接访问进程的主机虚拟地址。
  - **GHOST-ATTACK**：利用 GPU kernel 内存错误或攻击者 kernel 越过 GPU 边界，扫描并改写主机进程内存的攻击族。
- **单位与作者**：
  - Seoul National University：Sihyun Roh、Woohyuk Choi、Jaeyoung Chung、Yoochan Lee、Suhwan Song、Byoungyoung Lee
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00047)、[作者全文](https://leeyoochan.github.io/assets/pdf/ghost_SP_2026.pdf)
- **核心问题**：GPU 安全研究多把内存错误影响限定在显存，但新版 Linux 与 NVIDIA 驱动默认 HMM 后，GPU kernel 能访问主机地址；一个设备端越界是否能升级为主机 ASLR 绕过与控制流劫持成为新的边界问题。
- **方法与贡献**：GHOST-ATTACK 先借 GPU kernel 越界扫描主机映射，再覆盖 GOT 或函数指针劫持 PyTorch/Chrome 进程；防御 SHELL 用 LLVM 静态识别真正共享给 GPU 的区域，再由开源 NVIDIA 驱动页故障处理器执行细粒度白名单。
- **方法示例**：有漏洞的 PyTorch kernel 把超长主机缓冲区复制到 16 字节设备数组，覆盖设备函数指针；恶意 kernel 随后定位 `libcuda-rt` 的 GOT，把 `free` 改向调用系统函数的 gadget，转化为主机命令执行。
- **实验与证据**：在 Linux 6.8、NVIDIA 570 驱动与 RTX 4060 上成功攻击 PyTorch，并把恶意 kernel 嵌入 Chrome 138 WebGPU 路径验证主机地址泄漏和 `ioctl` 控制。SHELL 阻止全部实验变体；ERA5 真实应用端到端开销 0.9%，`mmap` 与页故障微基准分别增加 10.7% 和 12.1%。
- **局限与风险**：需要可利用的 GPU kernel 错误或执行攻击者 GPU 代码；Chrome 当前 WebGPU 不直接支持通用 kernel，因此该路径包含面向未来接口的原型假设。SHELL 目前基于 NVIDIA 开源驱动与 CUDA，AMD ROCm 和内存镜像模式尚未验证。
- **实践关系**：启用 HMM 的 ML/HPC 平台应把设备 kernel 当作能触及主机地址的代码，纳入内存安全审计、沙箱和最小共享区域；驱动升级不能只看性能，还应验证页故障访问控制。
- **推荐理由**：它证明统一地址空间同时统一了攻击影响面，并给出不需要应用手改、真实负载开销低于 1% 的对应防御。

### 10. VMSCAPE: Exposing and Exploiting Incomplete Branch Predictor Isolation in Cloud Environments

- **方向**：系统与硬件安全 / 云虚拟化瞬态执行
- **关键词**：Spectre-BTI、KVM/QEMU、分支预测器、跨虚拟机泄漏
- **名词解释**：
  - **vBTI**：跨 Guest/Host 的用户态与内核态边界污染分支目标预测器的虚拟化 Spectre-BTI 原语。
  - **IBPB**：软件请求 CPU 清除分支预测历史的屏障指令，安全性较强但频繁使用成本高。
- **单位与作者**：
  - ETH Zurich：Jean-Claude Graf、Sandro Rüegge、Ali Hajiabadi、Kaveh Razavi
- **出处与状态**：IEEE S&P 2026｜接收
- **公开或更新时间**：2026-05-18 正式发表
- **原文链接**：[IEEE S&P 官方接收页](https://sp2026.ieee-security.org/accepted-papers.html)、[DOI](https://doi.org/10.1109/SP63933.2026.00046)、[作者全文](https://comsec-files.ethz.ch/papers/vmscape_sp26.pdf)、[代码](https://github.com/comsec-group/vmscape)
- **核心问题**：CPU 厂商给 guest、host 和不同 VM 的预测器状态打标签或做切换清除，但把每个域当成单一实体，忽略 Guest User、Guest Supervisor、Host User 与 Host Supervisor 之间的组合。
- **方法与贡献**：作者系统枚举四种权限域的训练—受害组合，在 AMD Zen 1—5 和 Intel Coffee Lake 找到多种新 vBTI 原语；VMSCAPE 让恶意 guest user 污染 host user 的 QEMU 间接分支，再借推测 gadget 搜索并泄漏任意 QEMU 内存。
- **方法示例**：客户机反复训练与 QEMU 目标分支别名的地址，VM exit 后 QEMU 在宿主用户态误预测到泄漏 gadget；攻击者逐步定位磁盘加密上下文，并通过客户机可测的缓存通道还原密钥字节。
- **实验与证据**：端到端攻击在默认、未修改 QEMU 和 AMD Zen 5 上以 154 B/s 泄漏任意内存，字节准确率 99.85%，可恢复磁盘加解密密钥；原语还覆盖 AMD Zen 1—5 与 Intel Coffee Lake。逐次 VM exit 执行 IBPB 开销约 57%，选择性方案在 UnixBench 常见负载约 1%，retpoline 路线约 3.9%。
- **局限与风险**：端到端 exploit 只在特定 AMD Zen 5/KVM/QEMU 配置完成，跨型号原语不等于都可同速利用；定位分支和内存需要统计重复，云调度噪声及厂商补丁会改变可行性。部分防御仍依赖正确识别高风险切换。
- **实践关系**：云平台需把 host user 与 guest user 的预测器隔离纳入威胁模型，优先采用按转换路径选择性清除并跟踪微码；租户侧无法可靠检测这种宿主泄漏，应依赖平台披露和实例代际治理。
- **推荐理由**：它不仅发现隔离缺口，还从恶意客户机到未修改 QEMU 磁盘密钥完成整条攻击链，并量化可部署缓解的成本。
